| 2026-11-02 | **Fixed: Jacques 292 (edge-protected).** Not an ice rule: slot 14 had been turned into Chip's type by an earlier off-map write. When an object other than slot 0 arrives on a counted chip, the cartridge's pickup code acts on slot 0: it already cleared slot 0's moving flag (modelled), and it also writes floor as the tile under slot 0, before the state. Earlier measurements could not see that write because Chip stood on floor; here he was on ice. The remake now writes under[0] = floor too (doc 03 §3.8). Follow-up test with the real Chip on 25 tile kinds while a fake Chip picks up a chip (`tools/measure/fakechip.py`, 300 runs) found the next fix. |
| 2026-11-02 | **Fixed: objects standing still on an ice corner.** An object that is not moving on an ice corner (in practice: it starts the level there) is only turned by the corner, not set moving: a block keeps standing, Chip (who cannot steer on ice) stays put; the remake used to start them sliding. 1280 lock-step runs (Chip held each way, every monster type, blocks, each corner) all match after the fix (doc 03 §3.3, doc 09 §17). |
| 2026-11-02 | **Fixed (by the ice-corner fix): Jacques 637 (edge-protected).** Traced: bug slot 14 stands on the protected bottom row (20,31) facing south; its move check reads cell (20,32), which is slot 20's state byte, holding A6 = a reference to slot 38, a drowned monster's splash effect. The "monster bumps into a dying effect" rule erases it: water (slot 38's under-tile) is written into that "cell" (slot 20's state becomes 14: a glider facing north, not moving) and slot 38 is cleared, leaving its map reference behind. Remake and cartridge agree up to here; slot 20 then stands on an ice corner, and the old remake started it moving. Now in sync for all 3448 ticks. |
